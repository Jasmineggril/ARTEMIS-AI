ATUE COMO ENGENHEIRO DE SOFTWARE SÊNIOR, ESPECIALISTA EM QUALIDADE, MACHINE LEARNING, DOCUMENTAÇÃO TÉCNICA E COMPROVAÇÃO DE MATURIDADE TECNOLÓGICA TRL.

OBJETIVO

Auditar o projeto atual e preparar um pacote real, verificável e anonimizado de evidências para comprovar TRL 4.

A solução é uma plataforma preditiva de inteligência ambiental para prevenção de incêndios em áreas produtivas e ativos territoriais.

O pacote deverá comprovar que existem:

- arquitetura tecnológica definida;
- protótipo funcional;
- componentes integrados;
- entrada e processamento de dados;
- classificação de risco;
- fatores explicativos;
- recomendações preventivas;
- alertas;
- mapa;
- persistência dos resultados;
- testes em ambiente controlado;
- documentação das limitações.

REGRAS DE VERACIDADE

1. Não declarar como implementada nenhuma funcionalidade que não exista no código.

2. Não afirmar que existe Machine Learning supervisionado operacional se houver apenas motor baseado em regras.

3. Quando forem utilizados dados sintéticos, simulados ou históricos, identificar claramente essa condição.

4. Não apresentar métricas sintéticas como desempenho operacional real.

5. Não declarar testes aprovados sem executar os comandos e registrar o resultado.

6. Não declarar integração ativa com APIs ou bases externas sem comprovação técnica.

7. Toda funcionalidade deverá ser classificada como:

- implementada;
- demonstrativa;
- experimental;
- em desenvolvimento;
- prevista para a Prova de Valor.

8. Quando o modo de submissão anônima estiver ativo, remover nomes pessoais, empresa, instituição, e-mails, links e demais identificadores.

2. EXECUÇÃO OBRIGATÓRIA DOS TESTES
==================================================

Execute, conforme os scripts existentes:

npm install
npm run check
npm run test
npm run test:risk
npm run test:auth
npm run build

Para Python:

pip install -r python_service/requirements.txt
pytest python_service/tests -v

Caso exista modelo supervisionado:

python python_service/train_model.py
python python_service/evaluate_model.py

Também teste:

- GET /health;
- POST /analyze-risk;
- POST /api/risk-analysis;
- persistência da análise;
- geração de alerta;
- carregamento do mapa;
- geração de relatório;
- modo anônimo.

Não ocultar falhas.

Se um comando falhar:

1. registrar a falha;
2. corrigir o código;
3. executar novamente;
4. guardar o resultado final e o histórico da correção.
